# Модули системы

Описание основных разделов панели. Доступ к каждому экрану дополнительно ограничивается permissions ([ROLES.md](ROLES.md)).

## Дашборд

Сводная точка входа после авторизации: обзор состояния для текущего пользователя/tenant.

## Магазины (Stores)

CRUD магазинов сети: создание, редактирование, soft delete / restore / force delete. Базовая сущность для отделов, оборудования и экспорта.

## Отделы (Departments)

Структура магазина (например, «Молочка», «Напитки»). У заведующего доступ может быть ограничен своим `department_id`.

## Товары (Products)

Каталог SKU: размеры, атрибуты, импорт из файла. Используются при расстановке на полках.

## Оборудование

| Тип | Назначение |
|-----|------------|
| **Shelves** | Обычные полки с уровнями |
| **Coolers** | Холодильники с уровнями |
| **Stands** | Стенды / торговое оборудование |

Для части типов есть preview кода оборудования. Soft delete / restore / force delete — по permissions.

## Планограммы (Planograms)

Расстановка товаров на уровнях полок (placements): фейсинги, позиция, привязка к продукту. Основной рабочий инструмент мерчандайзинга.

## План этажа (Floor Plan)

Визуальный редактор торгового зала: позиция оборудования, стены (`Wall`), layout магазина (`StoreLayout`). Данные кэшируются (ключ layout в Redis по правилам проекта).

## Экспорт / Импорт

- **Export:** генерация JSON магазина, скачивание, отправка в Firebase, журнал `SyncLog`.
- **Import:** загрузка шаблона/файла товаров.

См. [FIREBASE.md](FIREBASE.md).

## Product Bot (обогащение габаритов)

Super Admin: очередь предложений по неполным SKU (`/product-bot`).

1. **Open Food Facts** — имя / объём / тип упаковки по EAN (кэш, RU→world hosts, без API key).
2. **Training rules** — типовые мм (диаметр/высота) для категории+объёма.
3. **Эвристика** — оценка W×H×D по `package_type` + `volume_ml`, если правила нет.
4. Ручное принятие / отклонение; при accept можно сохранить новое правило.

Планограмме нужны мм; OFF почти никогда не отдаёт точный диаметр — размеры берутся из правил/оценки.

## Пользователи

Управление пользователями tenant: роли, активность, комментарии. Super Admin видит шире.

## Арендаторы (Tenants)

Только для Super Admin (и соответствующих permissions): создание tenant, активация/деактивация, квоты/лимиты через сервисы.

## Настройки (Settings)

Профиль, смена пароля, **интеграции** (Firebase project/URL/credentials, engine URL/secret).

## Биллинг и админка коммерции

- Публичные тарифы (`/plans`).
- Подписка / подтверждение оплаты / реквизиты.
- Admin: планы, банковские счета, approve/reject платежей.
- Счета (invoices): PDF, email, mark paid.
- Юридические документы (оферта, privacy) + публичные страницы и PDF.

## Чат и уведомления

Внутренний чат (conversations / direct), heartbeat присутствия, realtime через Reverb. Уведомления — список / read / unread-count (также в API).

## Логи

- Audit (activity log)
- Login log
- System log (+ clear для привилегированных ролей)

## Database Viewer

Инструмент Super Admin: просмотр таблиц и выполнение SQL (осторожно на проде — только доверенные аккаунты).

## Публичные страницы

- Тарифы
- Оферта / политика конфиденциальности / PDF
